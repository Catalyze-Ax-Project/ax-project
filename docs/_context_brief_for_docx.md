## 3. 핵심 용어 — 변환 시 일관 유지 필수

### 3.1 4가지 핵심 개념

| 용어 | 뜻 | 영문 식별자 유지 여부 |
|---|---|---|
| **Plugin** | AI에게 먹이는 마스터 프롬프트 (md 단위). 모든 자산의 최소 단위 | 영문 그대로 |
| **Client** | 고객사 맥락 저장소 (Plugin의 한 종류) | 영문 그대로 |
| **Skill** | 재사용 작업 playbook (Plugin의 한 종류) | 영문 그대로 |
| **Agent** | 향후 외부 AI 에이전트 통합 (현재 미구현) | 영문 그대로 |

### 3.2 비개발자 친화 용어 매핑 (UI·문서 일관 적용)

| 개발자 용어 | 한국어 표기 |
|---|---|
| Commit | 변경 / 변경 이력 |
| Pull Request | 제안 (Proposal) |
| Review | 검토 |
| Issue | 의견 / 논의 (Discussion) |
| Merge | 반영 |
| Repository | 플러그인 |

**주의**: 본문에서 "Discussion / Proposal / Change" 같은 영문 용어가 등장하더라도 **임의로 한글로 풀어쓰지 마세요.** 본문이 의도적으로 영문을 유지한 경우입니다.

### 3.3 축적 루프 (Accumulation Loop) — 제품의 핵심 메커니즘

```
사용 → Discussion(의견) → Proposal(제안) → 검토 → 반영(Change) → 다음 사용
```

이 루프 표현이 본문에 여러 번 나옵니다. 도식·코드블록·표 어떤 형태로 나오든 **원형 그대로 유지**해주세요.

## 6. docx 변환 시 반드시 지킬 것

### 6.1 구조 보존
- 마크다운 헤딩 레벨(`#` ~ `####`)을 워드 제목 스타일(Heading 1~4)에 그대로 매핑
- 문서 맨 앞에 **자동 목차(TOC)** 추가 — Heading 1·2 기준
- 표(`|...|`)는 워드 표로 변환. 셀 정렬·헤더 행 굵게 유지
- 체크박스(`- [ ]`, `- [x]`)는 ☐ / ☑ 또는 워드 체크박스 컨트롤로 시각화
- 코드블록(```)은 고정폭 폰트 + 회색 배경 박스
- 인용(`>`)은 인용 스타일 적용
- 수평선(`---`)은 페이지 내 구분선

### 6.2 메타 정보
- 문서 제목: **Catalyze AX Project — 요구사항 정의서**
- 부제: **PM Level / 초안 v0.1 / 2026-04-25**
- 헤더 또는 표지에 위 두 줄 노출
- 페이지 하단에 페이지 번호

### 6.3 식별자·고유명사
- 다음 토큰은 **영문 그대로**: Plugin, Client, Skill, Agent, Combo, Discussion, Proposal, Change, ClientMeta, Catalyze, Ripple, Midnight, Squid, Harness, Phase 1/2/3, Admin, Overview, KPI, Phase, Vercel
